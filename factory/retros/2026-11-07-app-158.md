## What slipped
Nothing reached a PR or a gate. A multi-area roadmap epic got the agent-ready label. It mixed code work that belongs to a different repo (the marketing site) with manual owner-only work that needs third-party accounts and credentials, and it depended on an earlier phase that was still open. The pipeline's triage step estimated 16 tasks, above the 12-task cap, and blocked before any spec or code was written. It posted a split into five ordered sub-issues and flagged which parts are not agent work.
## Why the gate missed it
No gate covers this, and none should. Gates review diffs, and there was no diff. The factory handled it as designed: the size check in .claude/workflows/issue-pipeline.js (MAX_TASKS) stopped the run early and gave a usable split. The miss came from the input. The owner labelled an epic and tracker issue for a single agent run, and only the owner can scope it (create the sub-issues, name the marketing-site repo, do the manual tasks). The factory did not make a mistake here.
## Proposed change
(none) No factory change. The triage size cap caught the oversized, cross-repo, partly manual epic before any work and proposed a split. The fix is for the owner to create the proposed sub-issues and label only the agent-doable ones agent-ready.
