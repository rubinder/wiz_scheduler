## What slipped
The factory wrote an architecture cleanup issue that named the wrong pattern. factory/proposals.py maps the frontend layering rule fetch-outside-api to anti-corruption-layer, which is about translating vendor data. The architecture skill files that rule under thin-router: pages call frontend/src/api/, never the network. The implementer and the architecture reviewer were pointed at the wrong design rule, and the issue gave no scope boundary. The issue blocked after 3 rounds with open architecture, accessibility and ci findings. Those findings are with the owner, so the mislabel is the confirmed factory defect, not necessarily the only cause. The touched component also has accessibility problems the issue never mentioned (labels not tied to their inputs, an icon-only close button with no accessible name). Those are a likely source of the accessibility and ci churn, but that is inference.
## Why the gate missed it
No gate covers this class. The rule-to-pattern map in proposals.py is a hand-written copy of the skill. Its test (factory/tests/test_proposals.py) asserts the wrong value, so the test locks the bug in instead of checking it against the skill. The ci gate ran that test and it passed. Nothing compares the factory's issue text with the skill it cites, so every fetch-outside-api cleanup issue goes out with the wrong pattern.
## Proposed change
(mechanical-test) Add a factory test (factory/tests/test_proposals.py) that parses .claude/skills/architecture/SKILL.md. For each pattern section, it collects the rule ids named on that section's "Mechanical check" line. It then asserts that every entry in proposals._PATTERN maps to the section that names the rule, and that every frontend and backend ratchet rule id has an entry. In the same PR, fix the mapping: fetch-outside-api goes to thin-router. Check stripe-outside-billing too: the skill lists it under aggregate-root, but the map says fail-closed. Remove the assertion that pins the wrong value. Any future drift between issue text and the skill then fails the factory suite, which the ci gate runs.
