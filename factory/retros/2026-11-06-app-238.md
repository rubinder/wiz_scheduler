## What slipped
The factory wrote the cleanup issue itself, and the issue pointed the builder at the wrong architecture pattern. It said the fetch-outside-api violation belongs to `anti-corruption-layer`, which is about translating third-party vendor models. The architecture skill puts fetch-outside-api under `thin-router` ("pages and hooks call frontend/src/api/, never the network"). The right fix is to move the streaming call behind frontend/src/api/, extending the client's existing stream helper, and delete the allowlist entry. The issue sent the builder toward a vendor-translation rule that has nothing to do with this file. The architecture reviewer judges against the skill, so the builder's fix and the reviewer's yardstick disagreed, and the run used up its 3 rounds and stopped. A second rule in the same table is also wrong: stripe-outside-billing is filed as `fail-closed`, but the skill lists it under `aggregate-root`. So future cleanup issues for that rule would mislead the builder the same way.
## Why the gate missed it
No gate covers this class. The wrong text comes from the factory's own issue writer, the hand-written rule-to-pattern table in factory/proposals.py. No gate reviews issue text the factory writes, and nothing checks that table against the architecture skill. The existing factory test even pins the wrong value: it asserts that a fetch-outside-api body says `anti-corruption-layer`. So the error is locked in rather than caught. The accessibility and ci findings were not provided, so I can't confirm that the mislabel alone caused the block. Even so, it is a real, verifiable factory fault that misdirected this build.
## Proposed change
(mechanical-test) Add a test to factory/tests/test_proposals.py that reads .claude/skills/architecture/SKILL.md and splits it into its pattern sections. For every rule in the proposals rule-to-pattern table, it checks that the rule's name appears in the "Mechanical check" line of the section the table maps it to. It also checks that every rule named on any section's "Mechanical check" line is in the table. With the test in place, correct the two wrong entries (fetch-outside-api to thin-router, stripe-outside-billing to aggregate-root). Also change the existing test's `anti-corruption-layer` expectation to `thin-router`. A cleanup issue can then never cite a pattern the skill doesn't enforce for that rule.
