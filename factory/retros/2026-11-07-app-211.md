## What slipped
Nothing reached a PR. The issue was labelled agent-ready, but it asked for every untranslated app string in all 18 non-English locales to be translated, plus a separate Nigerian Pidgin pass, a wider whole-tree guard and native-speaker review. The factory estimated about 20 tasks against a cap of 12, so it blocked the issue before building and proposed five ordered sub-issues. The issue text itself already said to do the work one section at a time.
## Why the gate missed it
No gate covers this, and none needed to. The size check ran before any code was written and worked as intended: it stopped a run that was too big, explained why, and gave a split the owner can file as separate agent-ready issues. The cause was the scope of the issue, not a weak check or a missed review. The i18n gate would have run on each sub-issue's PR, and changes to the protected translation test wait for the owner anyway.
